# Untested Designer opt-in

The tested Designer and ModuleCommon hashes remain the default startup gate. Matching tested files need no Manager state. Any other build needs explicit acceptance of **WARNING: Untested on this version. Use at your own risk.** through Q-SYS Mod Manager with shared opt-in support. This source change requires coordinated Manager and Core delivery; older Core packages do not consume the opt-in.

Core reads `.qds-mod-manager/state.json` in its own Designer installation. The schema-2 state must have `suspended: false`, an enabled `mods-core` entry with the matching ID, and an `untestedRuntime` object containing schema 1, an absolute `target`, and `hostSha256`/`commonSha256`. The normalized target must match the current installation and both hashes must match its actual nonempty host files. The registry is capped at 1 MiB with a JSON depth limit of 32. Missing or invalid fields, duplicate relevant properties, unreadable files, and linked paths fail closed.

Manager writes this optional field as part of the same transaction as the mod files after warning acceptance. Suspending managed mods or disabling/removing Core clears it. Undo, recovery and failed-operation rollback restore the prior consent with the prior state. Exported profiles do not contain it. Copying an installation or updating either host file invalidates consent; accept the warning again through Manager. Core evaluates eligibility once at process startup, so close and reopen Designer after applying changes.

The offline host-compatibility harness covers default denial, the tested path, matching consent, mismatched installation/builds, disabled/suspended/removed Core, malformed/duplicate/oversized state, missing/empty host files and linked state. It can also consume a fixture written by Manager using `--manager-state <installation>`. These checks validate the shared handshake and failure behavior. They do not establish successful Designer initialization, hook behavior or compatibility on an untested version.
